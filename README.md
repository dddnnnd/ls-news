# Los Santos News — Recovery Release V13
Это восстановительная сборка: прежняя визуальная структура сайта и редакционный кабинет возвращены, роли остаются в новой пятиуровневой иерархии, а секция выбора изображений снова использует встроенный альбом из 18 иллюстраций и загрузку собственных фото. Кнопка «Подать объявление» в публичной части отсутствует.
## Файлы
- `index.html` — единственный файл сайта, который публикуется через GitHub Pages.
- `supabase/functions/` — исходники трёх действующих Edge Functions.
- `supabase/migrations/20261025084552_add_editorial_recovery_marker_v13.sql` — маркер одноразовой миграции старого локального контента в `lsn_articles`.
- `supabase/migrations/20261025084553_reopen_incomplete_editorial_recovery_v13.sql` — оставляет миграцию ожидающей завершения, если в базе нет новостей и рекламы.
- `supabase/migrations/20261025002211_add_server_side_edge_function_rate_limits.sql` — миграция ограничителя запросов, уже присутствующая в производственной базе.
- `supabase/sql/restore_primary_admin.sql` — восстановление роли администратора для точно указанной учётной записи Ray Westblock; выполняйте только если это действительно ваш аккаунт.
- `supabase/sql/inspect_profile_roles.sql` — read-only проверка ролей.
- `supabase/tests/security_invariants.sql` — read-only критические проверки доступа.
- `recovery/backups/` — резервные копии двух исходных HTML-версий для ручного отката. Их не публикует GitHub Pages.
## Важно о старых объявлениях и фотографиях
В одной из предыдущих сборок были явные вызовы `localStorage.removeItem()` для ключей `lsn_news_store_v20`, `lsn_ads_store_v20`, `lsn_columns_store_v20` и их старых версий, а затем в эти ключи записывались пустые массивы. Эти действия выполнялись в браузере пользователя. Точное содержимое индивидуальных рекламных карточек и загруженных фотографий не хранится внутри HTML-файла и не найдено в доступных резервных файлах/таблицах Supabase. Поэтому его нельзя восстановить из исходников автоматически, если не осталось экспортированной резервной копии браузера.
Сборка больше не очищает эти ключи при запуске, читает старые варианты хранилища, возвращает известную LSN-рекламную карточку о наборе в редакцию, возвращает три исходных новостных карточки и три авторские колонки. Фотоальбом и редактор рекламы снова доступны. После входа администратора одноразовая миграция может перенести доступный локальный контент в Supabase; затем серверный маркер предотвращает возврат удалённых материалов из старого кеша.
## Восстановление доступа администратора
1. Сначала откройте `supabase/sql/inspect_profile_roles.sql` в Supabase SQL Editor и проверьте отображаемую учётную запись.
2. Если используемый аккаунт — именно `Ray Westblock` с ID `b0e3286c-0bb3-4f89-b3b8-2a6f1dbc9bef`, выполните `supabase/sql/restore_primary_admin.sql`. Скрипт не меняет пароль и проверяет ID вместе с именем. Не запускайте его без изменений для другого аккаунта.
3. Миграции маркера редакционного восстановления `20261025084552_add_editorial_recovery_marker_v13.sql` и `20261025084553_reopen_incomplete_editorial_recovery_v13.sql` уже применены к указанному Supabase-проекту. Оба исходника находятся в архиве для истории. Маркер оставлен в состоянии ожидания, поскольку в базе обнаружены три колонки, но не обнаружено новостей и объявлений.
Текущий Supabase-проект уже имеет историческую миграционную цепочку, которой нет целиком в этом архиве. Не запускайте `supabase db push` из этого восстановительного репозитория как будто это чистая база. Миграции маркера уже применены напрямую к production-проекту; исходники оставлены в архиве. Файл `supabase/sql/reference_do_not_run_current_security_reconciliation.sql` — только справочная копия ранее применённого базового SQL, его не нужно повторно запускать при обычном восстановлении.
## GitHub Pages
Распакуйте архив и загрузите **содержимое папки**, чтобы `index.html` оказался в корне репозитория. В GitHub откройте **Settings → Pages** и выберите **GitHub Actions**. Workflow `.github/workflows/pages.yml` публикует только `index.html` и `_headers`, а не исходники SQL или Edge Functions.
## Обновление Edge Functions
Применение/развёртывание исходников через Supabase CLI (если вы изменяли функцию):
```bash
supabase link --project-ref kahtjjlnivxkyynfjtyd
supabase functions deploy admin-delete-user
supabase functions deploy username-login --no-verify-jwt
supabase functions deploy username-available --no-verify-jwt
```
Публичные функции `username-login` и `username-available` проверяют входные данные и используют серверный ограничитель частоты запросов. `admin-delete-user` требует JWT и отдельно проверяет роль `admin`. Секретный/service-role ключ остаётся только в серверной среде и никогда не должен появляться в `index.html` или GitHub.
## Проверки и пределы гарантий
Статический HTML разобран; встроенный JavaScript проверен через `node --check`; дублирующихся ID не обнаружено. Эти проверки не заменяют браузерный тест на опубликованном домене. После публикации проверьте вход, регистрацию, сохранение материала, загрузку фото, выбор иллюстрации, удаление и повторное обновление ленты.
На Supabase Free проверка паролей через HaveIBeenPwned остаётся недоступной по ограничению тарифа; сборка не пытается обходить это ограничение.
