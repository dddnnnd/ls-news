# Los Santos News

Статический сайт с Supabase Auth и публикациями.

## Подготовка Supabase

1. Откройте Supabase → SQL Editor, вставьте содержимое `supabase-setup.sql` и выполните его.
2. В Authentication → URL Configuration укажите `https://capable-sorbet-80311f.netlify.app` как Site URL и добавьте `https://capable-sorbet-80311f.netlify.app/auth.html` в Redirect URLs. Не используйте временные адреса Netlify Deploy Preview для писем.
3. Если не хотите настраивать SMTP, в Authentication → Sign In / Providers → Email выключите `Confirm email`: регистрация сможет сразу открыть кабинет без письма. Если подтверждение нужно оставить включённым, настройте SMTP отправителя в Supabase Auth.
4. Подтверждение email настраивается в Authentication → Sign In / Providers. Старая таблица `lsn_journalist_access` сохраняется, но больше не используется.
5. Новые аккаунты получают роль «Редактор». При выполнении SQL аккаунт `deeeenchik80@gmail.com`, если он уже зарегистрирован в этом проекте, автоматически получает роль `moderator`. Если аккаунт создан позже, повторно выполните блок назначения модератора или назначьте его через таблицу `public.lsn_user_roles` в Supabase. Не выдавайте эту роль другим людям, если не хотите дать им полный доступ к управлению редакцией. В кабинете модератор может найти пользователя по User ID, UUID, email или ссылке аккаунта и назначить ему только роль `journalist` или `editor`.

Роли по уровню полномочий: модератор → журналист → редактор. Все три роли могут публиковать и снимать с публикации свои материалы. Только модераторы могут менять роли других пользователей; это проверяется серверной SQL-функцией и RLS.

## Публикация сайта

Загрузите содержимое этой папки как статический сайт на Netlify или другой статический хостинг. Не открывайте `index.html` напрямую как `file://`: модули JavaScript должны загружаться с веб-сервера. После публикации завершите шаг 2 выше с реальным URL сайта.

`supabase-config.js` содержит публичный publishable key, предназначенный для браузера. Не вставляйте в файлы сайта `service_role` key или пароль базы данных. Доступ к данным ограничивается политиками RLS из SQL-схемы.

## Вход по User ID

При регистрации пользователь выбирает публичный User ID: 3–24 латинских букв, цифр или символов `_`. Его можно использовать для входа вместо email. Внутренний UUID по-прежнему создаётся Supabase автоматически. SQL-схема сохраняет выбранный ID и проверяет его уникальность.

После обновления `supabase-setup.sql` разверните серверную Supabase Edge Function отдельно от статических файлов Netlify. Функция принимает выбранный User ID или прежний UUID. Из корня этой папки выполните:

```sh
supabase functions deploy login-by-user-id --project-ref kahtjjlnivxkyynfjtyd --no-verify-jwt
```

Функция использует ключ `SUPABASE_SERVICE_ROLE_KEY`, автоматически предоставляемый Edge Functions. Он остаётся только на сервере Supabase; не добавляйте его в HTML/JavaScript или Netlify. Публичный publishable key передаётся SDK и не является секретом. JWT-проверка на шлюзе отключена, потому что пользователь ещё не вошёл. Функция ищет пользователя по выбранному ID или UUID и проверяет пароль через Supabase Auth; при неверных данных возвращает одинаковый ответ, не раскрывая email.

Если сайт опубликован на другом домене, добавьте его origin в `allowedOrigins` в `supabase/functions/login-by-user-id/index.ts` и заново разверните функцию.

## Готовые функции

- Публичная главная показывает только опубликованные статьи.
- Страница статьи: `article.html?id=UUID`.
- В форме статьи можно загрузить обложку JPG/PNG/WebP/GIF до 8 МБ; SQL создаёт публичный bucket `article-images` с загрузкой только в папку автора.
- Вход и регистрация открываются модальным окном поверх главной страницы; отдельная страница `auth.html` также поддерживается.
- Выбранный при регистрации User ID или email: модуль `auth.js`, таблица `lsn_user_profiles` из `supabase-setup.sql` и `supabase/functions/login-by-user-id/index.ts`.
- Редакторы, журналисты и модераторы могут публиковать свои материалы. Только модераторы видят управление ролями и могут менять должности других пользователей; права проверяются Supabase RLS и SQL-функциями, а не только интерфейсом.
- В кабинете → «Реклама» можно менять текст каждого баннера и удалять ненужные полосы. Для удаления баннеров примените обновлённую политику из `supabase-setup.sql`.
- В меню сайта при наведении на рубрику показываются последние материалы этой категории; щелчок фильтрует ленту публикаций.
- В кабинете можно искать материалы, фильтровать их по статусу, редактировать текст и обложку, публиковать или снимать с публикации.
- Карточки новостей и страница материала отображают автора и дату публикации. Для старых опубликованных материалов дата берётся из `created_at`, а имя автора заполняется из профиля при обновлении SQL.

Перед реальным запуском проверьте SMTP, Redirect URLs и примените SQL-схему в нужном Supabase-проекте.
